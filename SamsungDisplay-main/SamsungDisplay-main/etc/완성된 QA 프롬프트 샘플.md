## 🎯 실전 활용 통합 예시

### 완성된 QA 프롬프트 샘플
```
[Role]
당신은 핀테크 스타트업의 시니어 QA 엔지니어로서 결제 시스템 품질 검증을 담당합니다.

[Context]
우리 회사는 중소상인 대상 간편결제 서비스를 운영 중입니다. 
최근 PG사 변경에 따른 결제 모듈 전면 리팩터링이 완료되었으며, 
다음 주 정식 오픈을 앞두고 있습니다. 기존 월 평균 거래액 10억원 규모입니다.

[InputValues]
- 시스템: 결제 API 서버 (Spring Boot 3.2, Java 17)
- 변경사항: 토스페이먼츠 API 통합, 레거시 NICE페이 제거
- 지원 기능: 일반결제, 정기결제, 부분취소
- 테스트 데이터: 테스트 가맹점 계정 3개, 샌드박스 환경 제공
- 문서: Swagger API 문서, 시퀀스 다이어그램 첨부

[Step-by-step Instructions]
1. API 명세서 기반 기능 테스트 케이스 30개 이상 작성
2. SOLID 원칙 관점에서 리팩터링된 코드 검토 (특히 SRP, OCP)
3. 성능 테스트: JMeter로 동시 500TPS 부하 테스트
4. 보안 테스트: OWASP Top 10 체크리스트 검증
5. 결함 발견 시 Jira에 등록 및 재현 시나리오 작성
6. 최종 품질 리포트 작성 (릴리즈 Go/No-Go 판단 포함)

[Constraints]
- 테스트 기간: 3일 (실 작업시간 24시간)
- 자동화율 목표: 70% 이상 (RestAssured 사용)
- 운영 데이터 사용 금지 (GDPR 준수)
- Critical/High 결함 0건 달성 시 배포 승인

[OutputIndicator]
다음을 제공해주세요:
1. 테스트 케이스 목록 (Excel)
2. 자동화 테스트 스크립트 (Java/RestAssured)
3. 성능 테스트 결과 (TPS, 응답시간 그래프)
4. 코드 품질 분석 리포트 (SonarQube 기준)
5. 최종 QA 승인 보고서

[Output examples]
테스트 케이스 형식:
| TC ID | 분류 | 시나리오 | 입력 | 기대결과 | 실제결과 | 상태 |
|-------|------|---------|------|---------|---------|------|
| TC-001 | 기능 | 신용카드 즉시결제 | 금액:10,000원 | 승인성공 | 승인성공 | PASS |

결함 보고 형식:
[BUG-001] 정기결제 첫 결제 실패 시 재시도 로직 미작동
심각도: Critical / 재현율: 100% / 영향: 고객 이탈 우려
